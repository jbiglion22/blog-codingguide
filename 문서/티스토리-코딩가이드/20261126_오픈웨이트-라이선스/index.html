AI 모델을 내려받을 수 있다면, 마음대로 써도 될까요?
꼭 그렇지는 않습니다. 가중치는 공개했지만 한국에서는 쓰지 못하게 막은 모델도 있습니다.

[[ 이미지: 타이틀 (01-타이틀.png) ]]

이 글은 '오픈웨이트'와 '오픈소스'가 어떻게 다른지 정리합니다.
그리고 AI 모델을 쓰기 전에 라이선스에서 무엇을 봐야 하는지, 파이썬으로 확인하는 방법까지 다룹니다.

 

1. 가중치는 공개, 한국은 제외

중국 검색 기업 바이두는 대형 언어 모델 'ERNIE 5.5 Flash Base'의 가중치를 허깅페이스에 공개했습니다.
누구나 파일을 내려받을 수 있습니다.

그런데 함께 올린 라이선스 원문을 읽어 보면 조건이 붙어 있습니다.
제1.11조는 사용 허가 지역을 'EU·영국·대한민국을 제외한 전 세계'로 정합니다.
즉, 이 라이선스에서 한국은 허가 지역에 들어가지 않습니다.

제5.3조는 허가 지역 밖에서 모델과 파생 모델뿐 아니라, 이 모델로 만든 결과물을 사용·복제·수정·배포·표시하는 행위도 제한합니다.

이 제한은 이용자의 국적이 아니라, 모델과 관련 행위가 이루어지는 지역을 기준으로 합니다.

[[ 이미지: 제한이 따라가는 길 (02-제한이-이어지는-길.png) ]]

흥미로운 점은 같은 계열의 다음 모델입니다.
바이두는 Base 모델을 기반으로 파인튜닝한 'ERNIE 5.5 Flash Preview'도 공개했고, 모델 카드에 가중치에는 Apache 2.0을 적용한다고 적었습니다.

Apache 2.0이라는 라이선스 자체에는 지역 제한이 없습니다.
다만 Preview 설명에는 "이 라이선스는 Preview 가중치에만 적용되고, Base 모델은 자체 라이선스가 계속 적용된다"고 적혀 있습니다.

Preview는 Base에서 파생된 모델이기도 합니다.
그래서 실제로 쓸 수 있는 범위는 Preview 라이선스와 Base 라이선스의 파생 모델 조항을 함께 확인해야 합니다.
같은 회사, 같은 계열 모델이라도 라이선스가 다를 수 있고, 서로 얽혀 있을 수도 있다는 뜻입니다.

 

2. 오픈웨이트와 오픈소스는 무엇이 다를까

오픈웨이트(open-weight)는 학습이 끝난 모델의 가중치 파일을 공개했다는 뜻입니다.
가중치는 모델이 학습으로 얻은 숫자들이라, 이것만 있으면 내 컴퓨터나 서버에서 모델을 돌릴 수 있습니다.

하지만 '공개'와 '자유롭게 써도 된다'는 다른 문제입니다.
쓸 수 있는 범위는 함께 붙은 라이선스가 정합니다.

 

◆ 오픈소스의 공식 정의

'오픈소스'라는 말에는 공식 정의가 있습니다.
오픈소스 이니셔티브(OSI)의 「오픈소스 정의」입니다.

이 정의의 5항은 특정 사람이나 집단을 차별하지 말라고 합니다.
6항은 사업이든 연구든 사용 분야를 막지 말라고 합니다.

특정 나라에서 쓰지 못하게 하거나, 일정 매출을 넘으면 따로 허락을 받게 하는 라이선스는 이 기준에 맞지 않습니다.
그래서 이런 모델은 '오픈웨이트'라고는 할 수 있어도, 이 정의로 보면 오픈소스라고 부르기 어렵습니다.

 

◆ AI는 가중치만으로 부족하다

OSI는 2024년 10월 「오픈소스 AI 정의 1.0」도 내놓았습니다.
여기서는 가중치뿐 아니라 학습 코드와 학습 데이터에 대한 정보까지 공개해야 오픈소스 AI라고 봅니다.

비슷한 모델을 다시 만들어 볼 수 있을 만큼 알려 줘야 한다는 것입니다.
여기에 더해 누구나 목적에 관계없이 사용·연구·수정·공유할 수 있어야 합니다.

그래서 오픈소스 AI는 가중치만 공개한다고 충족되는 기준이 아닙니다.
학습 데이터 정보, 학습·실행 코드, 매개변수가 함께 공개되고 사용 조건도 자유로워야 합니다.

3. AI 모델 라이선스에서 볼 다섯 가지

라이선스 파일은 길지만, 먼저 볼 곳은 정해져 있습니다.
ERNIE 5.5 Flash Base 라이선스를 예로 들면 이렇습니다.

  • 지역: 어디서 쓸 수 있나 — 한국·EU·영국 제외(1.11조)
  • 상업 이용: 돈을 버는 서비스에 써도 되나 — 비상업은 무료. 관련 제품·서비스의 연 매출이 5천만 달러 이하이면 출처 표시와 1회 사용 통지, 넘으면 사전 서면 승인(4조). 관련 매출은 라이선스가 정한 제품·서비스와 계열사 기준으로 계산(1.7조)
  • 다른 모델 개선: 모델이나 결과물로 다른 AI를 개선해도 되나 — 제한(5.5조)
  • 표시 의무: 서비스 화면에 출처를 적어야 하나 — 상업 제품은 정해진 문구를 표시(3.2조)
  • 허용 용도: 금지된 쓰임이 있나 — 군사 목적, 사람에게 큰 영향을 주는 자동 결정 등 20개 항목(부속서 A)

특히 '다른 모델 개선' 조항은 놓치기 쉽습니다.
예를 들어 모델이 만든 답변을 모아 다른 AI 모델의 학습이나 성능 개선에 쓰려 한다면, 제5.5조의 제한에 해당하는지 확인해야 합니다.

 

4. 파이썬으로 라이선스 이름 확인하기

허깅페이스는 모델 정보를 API로 공개합니다.
설치할 것 없이 파이썬 기본 라이브러리만으로 라이선스 이름을 읽을 수 있습니다.

import json
import urllib.request

models = [
    "baidu/ERNIE-5.5-Flash-Base",
    "baidu/ERNIE-5.5-Flash-Preview",
]

for name in models:
    url = f"https://huggingface.co/api/models/{name}"
    with urllib.request.urlopen(url) as res:
        info = json.load(res)
    card = info.get("cardData", {})
    print(name)
    print("  license      :", card.get("license"))
    print("  license_name :", card.get("license_name", "-"))
    print("  commit       :", info.get("sha", "-")[:12])

실행하면 이렇게 나옵니다.

[[ 이미지: 파이썬 실행 결과 (04-파이썬-실행-결과.png) ]]

apache-2.0처럼 널리 쓰이는 이름이 나오면 그 라이선스의 표준 조건을 따르면 됩니다.
other는 허깅페이스의 표준 목록에 없는 라이선스라는 뜻입니다. 회사가 직접 정한 라이선스인 경우가 많습니다.

이때는 저장소의 LICENSE 파일을 열어 위의 다섯 가지를 직접 읽어야 합니다.
이 코드는 이름만 알려 줄 뿐, 조건까지 판단해 주지는 않습니다.

 

5. 모델을 쓰기 전에 해 둘 일

  • 모델을 고를 때 성능표와 함께 LICENSE 파일을 연다
  • 쓰려는 버전의 라이선스를 확인한다(같은 계열도 다를 수 있음)
  • 파생 모델과 결과물에도 조건이 이어지는지 본다
  • 확인한 날짜와 라이선스 버전, 허깅페이스 저장소의 커밋 ID를 기록해 둔다
  • 회사 서비스라면 법무 담당과 함께 검토한다

라이선스는 새 버전에서 바뀔 수 있습니다.
모델을 업데이트할 때마다 다시 확인하는 습관이 필요합니다.

위 코드가 함께 보여 주는 commit 값이 그 저장소의 버전입니다.
기록해 두면 나중에 라이선스 파일이나 모델 카드가 바뀌어도, 당시 어떤 버전을 썼는지 확인할 수 있습니다.
